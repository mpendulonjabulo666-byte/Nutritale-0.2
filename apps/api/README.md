# @nutritale/api

Express 5 + TypeScript (strict) API for NutriTale V1: accounts, user preferences and the
ingredient catalogue. Every input is validated with zod `.strict()` schemas (unknown fields are
rejected). Storage sits behind two interfaces, with an in-memory and a MongoDB implementation.

## Run

```
npm install                          # from the repository root
npm run typecheck -w @nutritale/api
npm test -w @nutritale/api           # vitest + supertest, in-memory storage
```

Local server with in-memory storage (no database; data is lost on restart):

```
cd apps/api
STORAGE=memory JWT_SECRET=<32+ random characters> npm run dev
```

Local server with MongoDB: copy `.env.example` to `.env`, fill it in, load it into the
environment (for example `set -a; . ./.env; set +a`) and run `npm run dev`. Never commit `.env`.
On start the API creates its indexes (see Storage). `npm start` runs the server with `tsx`.

Why `tsx` and no `tsc` build: the shared packages (`@nutritale/markets`,
`@nutritale/catalogue-search`) are TypeScript source with extension-less imports (needed by the
Expo bundler), which plain Node cannot load. So the API type-checks with `moduleResolution:
Bundler` and runs through `tsx`. A bundled production build (for example esbuild) is a follow-up
before deployment.

## Routes

All errors use one shape: `{ "error": { "code": "...", "message": "..." } }`. No stack traces or
library messages. Every response has an `X-Request-Id` header (always generated by the server).

| Method and path | Auth | Body or query | Success |
|---|---|---|---|
| `GET /health` | none | - | 200 `{ status: 'ok' }` |
| `POST /auth/register` | none, auth rate limit | `{ email, password (10-128), firstName, market, locale }` | 201 `{ user, accessToken, refreshToken, tokenType, expiresIn }` |
| `POST /auth/login` | none, auth rate limit | `{ email, password }` | 200 same as register |
| `POST /auth/refresh` | none, auth rate limit | `{ refreshToken }` | 200 `{ accessToken, refreshToken, tokenType, expiresIn }` |
| `POST /auth/logout` | Bearer | empty | 204, revokes the session |
| `GET /me` | Bearer | - | 200 `{ user }` |
| `PATCH /me/preferences` | Bearer | any of `{ market, locale, allergens, diets }` | 200 `{ user }` |
| `DELETE /me` | Bearer | `{ password }` | 204, deletes the user and all sessions |
| `GET /catalogue/search?q=&locale=` | none, catalogue rate limit | `q` up to 64 characters | 200 `{ status, results (max 8), didYouMean, suggestions, canAddCustom }` |
| `GET /catalogue/:id/substitutes?locale=` | none, catalogue rate limit | - | 200 `{ id, substitutes: [{ id, name, category, note }] }` |

- `market` is a code from `@nutritale/markets` (`ZA`, `GB`, `US`); `locale` is one of the market
  locales (`en-ZA`, `en-GB`, `en-US`).
- `allergens` must be in the user's market list (`allergenRule.allergens`); after a market change
  in the same request the new market's list applies. An allergen outside the list is refused
  (`allergen_not_in_market`), never silently dropped.
- `diets`: `vegetarian`, `vegan`, `halaal`, `no-pork`, `kid-friendly` (the prototype's chips).
- Error codes: `validation_error`, `unauthorized`, `invalid_credentials`, `invalid_refresh_token`,
  `email_taken`, `password_incorrect`, `allergen_not_in_market`, `not_found`, `rate_limited`,
  `request_error`, `internal_error`.

## Security design

- Passwords: Argon2id with `@node-rs/argon2` (prebuilt binaries, no native build step),
  19 MiB memory, 2 iterations, 1 lane (OWASP minimum). Password length 10 to 128.
- Login gives the same 401 (`invalid_credentials`) for an unknown email and a wrong password, and
  runs a dummy Argon2 check for unknown emails so timing is similar.
- Access token: HS256 JWT (`jose`), 15 minutes, `sub` (user id) and `sid` (session id) only;
  issuer and audience checked; only `HS256` accepted. Each request also checks that the session
  is still active, so logout and reuse detection take effect at once.
- Refresh token: 32 random bytes (base64url), stored only as a SHA-256 hash, 30 days. Each refresh
  revokes the used token and issues a new one in the same session family. A revoked token used
  again revokes the whole family (all its refresh and access tokens).
- Rate limits per IP: global, a tighter shared limit for register, login and refresh, and one for
  the catalogue. 429 answers in the JSON error shape. The counters are in process memory: with
  more than one instance each counts separately.
- Routes never take a user id: the id always comes from the verified token.
- Register returns 409 `email_taken` for an existing email. That tells a caller the email has an
  account; closing it needs email verification (not built yet). The auth rate limit slows probing.

## Environment

See `.env.example`. `src/env.ts` validates it; errors name the variable, never its value.

| Variable | Default | Note |
|---|---|---|
| `STORAGE` | `mongo` | `memory` for tests and local runs; refused with `NODE_ENV=production` |
| `MONGODB_URI`, `MONGODB_DB` | - | required when `STORAGE=mongo` |
| `JWT_SECRET` | - | required, 32+ characters |
| `CORS_ORIGINS` | empty | comma-separated |
| `RATE_LIMIT_WINDOW_MS`, `RATE_LIMIT_MAX` | 15 min, 300 | global |
| `AUTH_RATE_LIMIT_WINDOW_MS`, `AUTH_RATE_LIMIT_MAX` | 15 min, 20 | register, login, refresh |
| `CATALOGUE_RATE_LIMIT_WINDOW_MS`, `CATALOGUE_RATE_LIMIT_MAX` | 1 min, 60 | catalogue |
| `JSON_BODY_LIMIT` | `100kb` | |
| `PORT`, `NODE_ENV` | 4000, development | |

## Storage

`src/storage/types.ts` defines `UserRepo` and `SessionRepo`.

- `src/storage/memory.ts`: in-memory, used by the tests and `STORAGE=memory`.
- `src/storage/mongo.ts`: official `mongodb` driver, connects only when `STORAGE=mongo`.
  Collections `users` (unique index on `emailLower`) and `sessions` (one document per refresh
  token: unique index on `tokenHash`, indexes on `familyId` and `userId`, TTL index on
  `expiresAt`). Filters are built only from validated strings. **UNVERIFIED**: never run against
  a database (the `mongodb-memory-server` binary download was blocked in the build session).

## Postman

Collections 01, 02 and 04 are in `docs/postman/`, generated by
`docs/postman/generate_collections.py`. Run each against a fresh `STORAGE=memory` server (each
collection ends by driving a rate limit to 429):

```
npx newman run docs/postman/01-authentication.postman_collection.json -e docs/postman/local.postman_environment.json
```
